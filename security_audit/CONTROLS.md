## Common request pipeline

For ordinary HTTP requests, effective user-middleware order is:

```text
SecurityHeaders -> ErrorSafety -> Admission -> BodySizeLimit -> CSRF
                -> FastAPI parsing/dependencies -> async route rate check -> handler
```

Starlette's outer error layer also exists. ErrorSafety catches unexpected HTTP exceptions before server traceback handling and supplies a generic 500 if no response has started. After headers have been sent, it raises only a sanitized interruption exception with the original exception context suppressed; it cannot replace the status or retract delivered data. The generic fallback exception handler also supplies security headers explicitly. `GET /healthz` short-circuits in admission with a fixed response before body, CSRF, concurrency and storage work; outer response security headers still apply. Non-HTTP scopes bypass these HTTP policies; the application defines no WebSocket routes.

## Route inventory

The table enumerates the 30 explicit HTTP method/path operations and the static mount. Debug documentation routes are listed separately. All entries inherit the common pipeline unless an exception is stated. `U` means a cookie session checked against signature, expiry, required claims, `jti` revocation, refreshed account, tombstone and epoch. `A` adds current database `is_admin`. `H` means matching CSRF cookie/header; `F` means matching required form field/cookie; `S` means safe method without unsafe-request CSRF. Mutating user/admin routes revalidate the cookie after the relevant database lock. Header/body/form validation can reject a request before the handler's business logic.

Default route budgets: pages 120/minute; OAuth callback 60/minute; local login 10/minute/IP plus 5/minute/account; token reads 60/minute; token writes 30/minute; session 30/minute; account deletion 5/minute; admin 120/minute; bearer validation 600/minute. Authenticated budgets use user-or-IP; public/bearer budgets use IP. Pre-auth IP admission is shared across ordinary paths in addition to these route budgets.

| --- | --- | --- | --- |
| `GET /healthz` | Public; fixed response before CSRF middleware | No route limit; fast path bypasses IP counter and concurrent cap | Liveness only `{status: ok}`; no body read or DB/Redis query. Response security headers apply. Other methods are not granted a health route by this fast path. |
| `GET /readyz` | Public; S | Pre-auth IP admission and concurrent cap; no separate route limit | Bounded default 2-second database `SELECT 1` and Redis health check; ready or sanitized 503. Monitor reachability is an operational choice. |
| `GET /` | Public; S | IP / pages | Login/configured display page; no authorization data mutation. Templates must only render intended non-secret configuration fields. |

| `GET /oauth/openid/callback` | Public entry; matching state cookie and verifier before code exchange | IP / callback | Bounded fixed-provider calls; creates or refreshes account; bootstrap role only for new rows; tombstone recheck before JWT issuance; 303 dashboard and session cookie; clears OAuth cookies on success. | `GET /login/local` | Public; S; 404 if local disabled | IP / pages | Local login form; matching form token on first visit; no DB write. |

| `POST /admin/tokens/search` | A; F even when header supplied | User-or-IP / admin | Bounded plaintext token in POST body, HMAC lookup; results metadata. No credential echo/URL query. No authorization-state write. |

### User credential operations

Source: [tokens.py](../app/api/tokens.py). Every operation uses U; all mutations use H, owner lock and post-lock cookie revalidation. Individual token queries include the current owner, not merely the supplied token ID. Creation quota counts all stored tokens, including expired/revoked rows; deletion frees quota.

| Method/path | Additional authorization / limits | Route budget | Durable effect / response |
| --- | --- | --- | --- |
| `GET /tokens` | Own account only; S | Read | Own metadata sorted by creation; no digest/value. List is bounded by configured per-user stored-token quota for normal newly managed accounts. |
| `POST /tokens` | Locked owner; default quota 100; name bounded; one unambiguous expiry choice; future expiry within configured maximum | Write | Cryptographically random value, default 32 random bytes, persisted HMAC; finite default 90-day lifetime, max 365 days. Plaintext only in creation response. Concurrent creates serialize quota check and insertion. |
| `POST /tokens/revoke-all` | Locked owner and post-lock session recheck | Write | Bulk mark own API tokens revoked and atomic session-epoch increment in one transaction; all existing own sessions become unusable, including current. Account can log in again. |
| `DELETE /tokens/{token_id}` | Own token or 404 | Write | Marks credential revoked; keeps metadata; future validation rejects it. |
| `DELETE /tokens/{token_id}/permanent` | Own token or 404 | Write | Deletes record; future validation cannot find credential. |
| `POST /tokens/{token_id}/renew` | Own token; same expiry bounds/default duration rules | Write | Changes expiry, returns metadata. Does not generate a new key or clear revocation. Extending an expired credential can make that same value valid again if not revoked. |
| `POST /tokens/{token_id}/rotate` | Own token; token row locked; revoked token denied; finite expiry bound | Write | Replaces digest with newly generated value and resets usage timestamp; old value rejected. New plaintext only in rotation response. |

### Administrative operations

Source: [admin.py](../app/api/admin.py). Every operation uses A and user-or-IP admin budget. Read operations use S. Mutations require H, lock and refresh the acting administrator, serialize administrator-membership decisions, and revalidate the session after locking. Targeted user mutations load the target with a row lock. Administrator authority intentionally crosses ownership boundaries; controls do not constrain a malicious authorized administrator to their own account.

| Method/path | Additional authorization / limits | Persistence / response |
| --- | --- | --- |
| `GET /api/admin/tokens` | Bounded page and page size (default 20, max 100) | All token/user metadata; no token digest/value/password hash. |
| `DELETE /api/admin/tokens/revoked` | Locked current admin | Bulk permanent delete of revoked records only; count/audit. Active records retained. |
| `DELETE /api/admin/tokens/{token_id}` | Locked current admin | Mark any selected token revoked; metadata retained. |
| `DELETE /api/admin/tokens/{token_id}/permanent` | Locked current admin | Delete any selected token record. |
| `GET /api/admin/users` | Bounded page and page size | Profiles, provider subjects, roles and password-presence flag; no password hash. These are privileged personal data. |
| `POST /api/admin/users` | Bounded fields; normalized local email uniqueness; new password policy and bounded off-loop hash | Explicit local account creation and optional admin role; lifts only local-email tombstones, never OAuth-subject tombstones. No public registration. |
| `PATCH /api/admin/users/{user_id}` | Password rejected for OAuth account; protect last usable admin; target row lock | Optional name/password/role update. Password or actual role change atomically increments epoch; name-only does not. Existing API tokens remain valid unless explicitly revoked. Disabled admin rows can be explicitly demoted; uncertain alternative availability returns 503. |
| `DELETE /api/admin/users/{user_id}` | Cannot delete self through this endpoint; last usable admin protected; target row lock | Tombstone and cascade account/token/revocation-row deletion one transaction. Disabled orphan admin rows can be explicitly cleaned up by a usable admin; uncertain alternative availability returns 503. Self deletion uses separate protected route. |
| `POST /api/admin/users/{user_id}/revoke-credentials` | Locked current admin and target user | All target API tokens marked revoked and epoch incremented atomically; account can subsequently authenticate again. |
| `POST /api/admin/users/restore-oauth` | Explicit bounded provider-subject input; locked current admin | Deletes matching subject tombstone(s), allowing future OAuth creation/login. No old token/session restoration; does not restore unrelated local email identity. |

### API credential validation and development-only documentation

| Method/path | Authentication / request binding | Rate / persistence / limits |
| --- | --- | --- |
| `POST /api/v1/auth/validate` | Explicit exact-prefix Bearer header only; maximum token length 256; no browser-cookie fallback. Matching bearer skips CSRF. Without a bearer, middleware can return 403 before handler 401 unless CSRF is supplied. | IP validation budget; configured source CIDRs exempt exact validation path from both IP admission and validation counter, not concurrency/body/header policies. Indexed HMAC lookup, non-revoked token, existing owner, no tombstone and non-expired lifetime. Returns `{valid, user_id, expires_at}`. Best-effort conditional usage-date write at most once per configured interval (default 60 seconds); telemetry write failure cannot turn a successful authorization into a 500. |
| `GET /docs`, `GET /redoc`, `GET /openapi.json` | Public only when debug enabled; S | Debug off and forbidden in production. If enabled in development, inherit pre-auth admission/body/headers and no route-specific budget. No persistence. Strict self-script CSP may restrict external documentation assets; these are developer conveniences, not production control paths. |

Unmatched routes/methods and framework redirect/error responses also meet the outer pipeline. A declarative `ValidateRequest` class exists, but the implemented credential contract is the Authorization header, not a JSON-body token. There is no `/token` password-grant endpoint, public registration endpoint, or WebSocket endpoint despite auxiliary OAuth metadata/helpers.

## Evidence interpretation and unimplemented policies

[test_auth_fixes.py](../tests/test_auth_fixes.py), [test_api_fixes.py](../tests/test_api_fixes.py), [test_admission_fixes.py](../tests/test_admission_fixes.py), and the existing security/API/model/cookie/token suites are regression sources for the current controls. Some business-logic tests deliberately call undecorated handlers or helpers with synthetic requests; these exercise transaction and ownership behavior but cannot by themselves prove middleware/dependency/rate execution order in real HTTP traffic. Admission tests explicitly verify rejection before body/auth work. Isolated HTTP probes and final integrated test results should be read with their associated configuration, backend and revision evidence.

The saved [probes/](probes/) scripts and [baseline/](baseline/) notes document original vulnerabilities and synthetic reproductions; an old result such as two successful quota-race creates or zero remaining admins is **historical pre-fix evidence**, not a current regression-suite assertion. Similarly, an earlier PostgreSQL test result does not establish every later patch was tested against production PostgreSQL/TLS/Redis. Current [SQLite test output](evidence/final-sqlite-tests.txt), [PostgreSQL test output](evidence/final-postgres-tests.txt), [coverage](evidence/final-coverage.json), and disposable [PostgreSQL runtime](evidence/final-postgres-runtime-test.json) / [Redis runtime](evidence/final-redis-runtime-test.json) evidence are kept as raw artifacts. Their configuration, revision and scope interpretation belongs in [REPORT.md](REPORT.md); this document deliberately does not hardcode evolving dataset counts or substitute test presence for a deployed assurance claim.

The following capabilities are not implemented by this service and require explicit operational decisions:

- Complete ID-token/OIDC validation, multiple-provider issuer namespace, application-enforced MFA, step-up or recent authentication, local self-service reset, and idle-session timeout.
- Automatic IdP logout/disable ingestion, automatic API-token revocation on password/role change, resource scopes/tenant/model entitlements, and downstream authorization-cache invalidation.
- A non-destructive versioned HMAC-key rotation/migration, scheduled blacklist cleanup, centralized tamper-resistant audit collection, comprehensive compromised-password data and security alerting.
- Live TLS/ingress/network/least-privilege verification, encrypted tested backups, disaster recovery, production load/DoS certification, and closure or documented acceptance of all image vulnerabilities.

Use the threat-model operational questions and the production runbook to obtain those external guarantees before accepting a production deployment.
